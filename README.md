# PKNU 기숙사 식단 위젯
 
iOS Scriptable 기반 자동 식단 파싱 위젯 모음
국립부경대학교(PKNU) 학생들이 실제로 지내는 두 기숙사 — **세종기숙사**(학교 직영, `dormitory.pknu.ac.kr`)와 **부경대행복기숙사**(한국사학진흥재단 위탁, `happydorm.or.kr`) — 의 오늘자 식단을 각각 홈 화면 위젯으로 바로 확인할 수 있는 프로젝트입니다.
 
두 기숙사는 완전히 다른 시스템(다른 회사, 다른 서버, 다른 마크업 구조)을 쓰기 때문에 스크립트도 서로 별개 파일로 나뉘어 있습니다. 자신이 사는 기숙사에 맞는 스크립트 하나만 설치하면 됩니다.

## 🗂 공통 동작 방식: 캐싱
 
두 위젯 모두 같은 방식의 캐싱을 씁니다.
 
- 위젯을 열 때마다 **항상 서버에 새로 요청**합니다 (학교나 재단 쪽에서 식단을 중간에 수정해도 바로 반영되도록, 하루 1회만 크롤링하는 방식은 쓰지 않습니다)
- 성공하면 그 결과를 화면에 표시하면서 동시에 로컬 파일에 덮어써 둡니다
- 이 요청이 인터넷 문제로 실패하면, 그제서야 마지막으로 저장해둔 캐시를 대신 보여줍니다
  - 그 캐시가 오늘 크롤링해둔 것이면 "방금 갱신 실패, 최근 데이터 표시"라고 안내
  - 며칠 전 캐시라면 "⚠️ 9/25 기준 (오프라인, 갱신 실패)"처럼 날짜를 명시해서 오늘 식단으로 착각하지 않게 함
- 캐시조차 하나도 없는 상태(최초 실행 + 그 순간 인터넷도 없음)에서만 **"📶 인터넷 연결 없음"** 화면을 보여줍니다
- 캐시 파일은 위젯마다 하나씩만 계속 덮어쓰는 방식이라(`pknu_sejong_meal_cache.json`, `happydorm_busan_meal_cache.json`) 오래 써도 용량이 쌓이지 않습니다(항상 수 KB 수준)
## 🏠 세종기숙사 위젯
 
### 동작 방식 (실제 서버 응답 분석 기준)
 
`03_notice/notice01.php` 페이지 자체의 HTML에는 식단이 들어있지 않습니다. 페이지가 열리면 자바스크립트가 아래 엔드포인트로 AJAX 요청을 보내서 실제 식단표 HTML을 받아온 뒤 화면에 채워 넣는 구조입니다.
 
```
POST https://dormitory.pknu.ac.kr/03_notice/req_getSchedule.php
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
 
vt=<유닉스 타임스탬프(초)>&bid=foodE
```
 
- `vt`는 "그 주(일~토)에 속하는 아무 시각"이면 됩니다. 지금(now)의 타임스탬프를 넣으면 이번 주 식단표가 옵니다.
- `bid`는 식당 구분값이며, 세종기숙사는 `foodE` 고정입니다.
응답 HTML 구조:
 
- `<thead>`의 `<th>`에는 `요일(M/D)` 형식(0 채움 없음, 예: `월(5/11)`)으로 날짜가 들어있습니다. 실제로 확인한 형식은 이 한 가지뿐이었습니다.
- `<tbody>`에는 아침/점심/저녁 3개 행이 있고, 각 행은 `라벨(아침 등) + 일~토 7칸` = 8개의 `<td>`로 구성됩니다.
- 각 끼니 칸의 메뉴는 `<br />`로 줄바꿈되어 나열되며, 메뉴가 없으면(주말/방학/미운영) 칸이 완전히 비어 있습니다.
- 점심 행 앞에는 `<!-- <td class="wh">점심</td> -->` 같은 죽은 주석이 섞여 있어서, 주석을 먼저 제거하지 않고 파싱하면 셀 인덱스가 하나씩 밀리는 버그가 생깁니다.
파싱 흐름:
 
1. 오늘(KST) 날짜 계산
2. 지금 시각을 `vt`로 AJAX 요청 → 응답에서 HTML 주석 제거
3. `<th>` 7개에서 날짜를 파싱해 오늘 날짜와 일치하는 열 인덱스를 찾음
4. 못 찾으면(드문 경우) 응답에 포함된 이전주/다음주 버튼의 정확한 타임스탬프로 재요청
5. 아침/점심/저녁 행에서 해당 열의 셀을 꺼내 `<br />` 기준으로 정리(별표 `*` 제거, 줄바꿈 → 구분자로 합침)해서 위젯에 렌더링
### 대상 식당
 
| 항목 | 값 |
|---|---|
| 캠퍼스 | 세종기숙사 1,2관 (대연캠퍼스) |
| bid | foodE |
| 출처 | https://dormitory.pknu.ac.kr/03_notice/notice01.php |
| AJAX 엔드포인트 | https://dormitory.pknu.ac.kr/03_notice/req_getSchedule.php |
 
### 참고
 
- 학교 홈페이지가 AJAX 응답 구조(태그명, 클래스명 등)를 바꾸면 파싱 로직 업데이트 필요
- 실기기 테스트 결과 Referer/X-Requested-With 헤더, 한글 인코딩 모두 문제 없이 정상 동작 확인됨 (별도 조치 불필요)
## 🏠 부경대행복기숙사 위젯
 
### 동작 방식 (실제 서버 응답 분석 기준)
 
세종기숙사와 달리 이 사이트는 AJAX 호출이 필요 없습니다. 페이지 하나(`https://happydorm.or.kr/busan/ko/0605/cafeteria/menu/`)를 그냥 불러오면 이번 주(월~일) 7일치 식단표가 아래처럼 전부 정적으로 이미 박혀 있고, 화면의 요일 버튼은 그중 하나만 보여주고 나머지는 JS로 숨기는(`show/hide`) 방식일 뿐입니다.
 
```html
<table class="table__week week_menu_YYYY-MM-DD">...</table>
```
 
그래서 오늘 날짜에 해당하는 `<table>`만 정규식으로 잘라내면 됩니다 (GET 요청 한 번, POST/AJAX 불필요).
 
각 날짜 테이블 안에는 조식/중식/석식 3개 구간이 있고, 구간마다 "일반메뉴" + (끼니에 따라) "샐러드/후식" + "TAKE - OUT" 행이 있습니다. PC용 칸(`class="meal__PC"`)과 모바일용 중복 칸(`class="meal__M"`)이 나란히 들어있어서 PC용 칸만 골라서 씁니다.
 
파싱 흐름:
 
1. 오늘(KST) 날짜를 `YYYY-MM-DD` 형식으로 계산
2. 페이지 전체를 GET으로 가져옴 (브라우저처럼 보이는 User-Agent 헤더 사용 — 아래 참고)
3. 오늘 날짜와 일치하는 `week_menu_YYYY-MM-DD` 테이블만 정규식으로 추출
4. 그 안에서 조식/중식/석식 구간을 각각 잘라냄
5. "일반메뉴" 내용은 라벨 없이, "TAKE - OUT"·"샐러드/후식"처럼 부가 항목은 `라벨 : 내용` 형태로 표시
6. "정식 : ..." / "일품 : ..."처럼 원래 줄바꿈되어 있던 항목은 위젯에서도 줄바꿈 유지
### 대상 식당
 
| 항목 | 값 |
|---|---|
| 사이트 | 부경대행복기숙사 (happydorm.or.kr 계열 중 busan) |
| 출처 | https://happydorm.or.kr/busan/ko/0605/cafeteria/menu/ |
| 위젯 파라미터 | 다른 happydorm 계열 사이트(대구/세종/천안 등) 전체 URL을 넣으면 그 사이트로 대체 가능 |
 
### 참고
 
- 이 서버는 일반적인 HTTP 클라이언트 요청을 막는 봇 차단이 걸려 있어(테스트 중 403을 받음), 브라우저처럼 보이는 User-Agent를 붙여서 요청합니다. 그래도 막히면 헤더를 더 보강해야 할 수 있습니다.
- 스크립트에 `CACHE_VERSION` 값이 있어서, 파싱 로직을 고칠 때마다 이 값을 올리면 예전 버전으로 저장된 캐시가 자동으로 무효화됩니다 (스크립트만 갈아끼우고 캐시는 안 지워서 옛날 결과가 계속 보이는 문제 방지)
## 📱 사용 방법 (공통)
 
1. iOS 앱스토어에서 Scriptable 설치
2. 자신이 사는 기숙사에 맞는 스크립트 코드 복사 (`PKNU_세종기숙사_식단위젯.js` 또는 `부경대행복기숙사_식단위젯.js`)
3. Scriptable에 새 스크립트 생성 → 붙여넣기
4. 홈 화면에 Scriptable 위젯 추가 후 스크립트 연결
> ✅ 두 위젯 모두 실제 iOS 기기 + Scriptable 위젯에서 정상 동작 확인 완료. 오늘 날짜에 맞는 조식·중식·석식이 잘 표시됩니다. 방학 등으로 그 주 식단표 자체가 비어 있는 경우엔 "제공 없음"으로 뜨는 게 정상 동작입니다.
 
## ⚠️ 공통 참고
 
- GitHub는 JavaScript 실행을 지원하지 않음 (위젯은 Scriptable에서만 동작)
- 위젯은 열 때마다 항상 새로 크롤링하므로 평소엔 캐시를 신경 쓸 필요가 없음. 캐시 파일은 인터넷이 끊겼을 때만 쓰이는 비상용 백업이며, 지우면 그다음 오프라인 상황에서는 바로 "인터넷 연결 없음"이 뜨게 됨
